# P1.4 Lease API Contract

**Status: COMPLETE — LOCKED**

## Scope

P1.4 exposes the P1.3 Lease Service through a workspace-scoped, read/write API boundary without creating a competing domain authority.

## Endpoints

- `GET /api/leases/` — workspace-scoped lease list.
- `POST /api/leases/create/` — manager-level lease creation; delegates to `create_lease`.
- `GET /api/leases/<id>/` — workspace-scoped lease detail.
- `POST /api/leases/<id>/update/` — manager-level mutable-field update; delegates to `update_lease`.
- `POST /api/leases/<id>/transition/` — manager-level lifecycle transition; delegates to `transition_lease`.

## Authorization

- Read endpoints require `WorkspaceStaffPermission`.
- Mutation endpoints require `WorkspaceManagerPermission`.
- Unauthenticated requests are rejected by the existing workspace permission layer.
- Workspace membership and RLS remain authoritative; no endpoint accepts a client-supplied workspace as an override.

## Contract Rules

1. Lease mutations are delegated to the P1.3 service layer.
2. Lease status is read-only in the general lease serializer; lifecycle changes use the transition endpoint only.
3. Serializer validation rejects invalid date ordering and negative monetary values before mutation.
4. Responses use the existing `data` envelope for successful resources and `error` for service-level validation failures.
5. Workspace-scoped lookup prevents cross-workspace lease disclosure.
6. Reporting and financial-core state are not mutated by these endpoints.
7. Existing P1.2 model constraints, indexes, OneToOne occupancy relationship, RLS, and P1.3 lifecycle semantics remain unchanged.

## Validation/Error Boundary

- Serializer validation errors return HTTP 400.
- Domain `ValidationError` from the Lease Service returns HTTP 400.
- Missing lease in the active workspace returns HTTP 404.
- Workspace/role permission failures remain governed by the existing permission layer.

## Regression Coverage

The P1.4 API regression suite covers:

- successful creation;
- workspace-scoped list/detail behavior;
- cross-workspace detail isolation;
- manager-only create/update/transition mutations;
- unauthenticated request rejection;
- invalid lifecycle target handling;
- invalid date and negative-money validation;
- read-only status serializer behavior through the API contract.

## Lock Decision

P1.4 is an API boundary over the already locked P1.3 Lease Service. No alternate mutation path, financial authority, or workspace isolation mechanism is introduced. Final lock is valid only with the latest commit passing the complete CI gate: migration graph, migrations, RLS + FORCE RLS, full Django test suite, and system checks.
