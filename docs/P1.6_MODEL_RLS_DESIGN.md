# AjnihaStay — P1.6 Model & RLS Design

**Status:** DESIGN LOCK CANDIDATE  
**Version:** 1.0  
**Date:** 2026-09-14  
**Branch:** `phase-p1.5/termination-service`

## 1. Purpose

This document converts the P1.6 KYC & Agreement Foundation specification into an implementation-safe data model and PostgreSQL RLS design. It is intentionally additive and must not rewrite Tenant, Occupancy, Lease, ContractVersion, or financial authority.

## 2. Existing Architecture Verified

Current production relationships are preserved:

```text
Workspace
  └── Property
       └── Unit / SubUnit
            └── Occupancy
                 └── Tenant
                      └── Lease (OneToOne with Occupancy)
                           └── ContractVersion[]
```

Tenant currently contains legacy KYC fields `id_proof_type`, `id_number`, and `id_document`. These remain compatibility surface during P1.6 rollout. The current Tenant service also accepts the legacy document upload, so P1.6 must introduce a new secure path without silently breaking the existing create contract.

## 3. New Bounded Models

### 3.1 KycProfile

OneToOne with Tenant.

Required fields:

- `tenant` — OneToOne, PROTECT
- `workspace` — FK, PROTECT
- `status` — enum: `unverified`, `pending`, `verified`, `rejected`
- `verified_at`, `verified_by`
- `rejected_at`, `rejected_by`, `rejection_reason`
- `created_at`, `updated_at`

Constraints:

- unique tenant/profile;
- tenant and profile workspace must match;
- verified/rejected metadata must be internally consistent;
- workspace is mandatory.

### 3.2 KycDocument

Many documents per Tenant.

Required fields:

- `tenant` — FK, PROTECT
- `workspace` — FK, PROTECT
- `document_type`
- `document_number`/reference where applicable
- `file` or private storage reference
- `status`: `uploaded`, `under_review`, `verified`, `rejected`, `expired`
- `issued_at`, `expires_at`
- `uploaded_by`, `uploaded_at`
- `verified_at`, `verified_by`
- `rejected_at`, `rejection_reason`
- `created_at`, `updated_at`

Constraints:

- tenant workspace must equal document workspace;
- uploader/reviewer must be active workspace members when present;
- `expires_at >= issued_at` when both exist;
- lifecycle statuses must be valid.

Replacement policy: a replacement creates a new document record. Existing records remain historical evidence.

### 3.3 KycVerificationEvent

Append-only verification history.

Fields:

- `workspace`
- `kyc_profile`
- `tenant`
- `from_status`
- `to_status`
- `actor`
- `occurred_at`
- `reason`
- `metadata`
- deterministic `event_key`
- `created_at`

Constraints:

- workspace/profile/tenant must be mutually consistent;
- event key unique per profile when present;
- no update/delete through the application contract.

### 3.4 AgreementLink

Relationship/indexing foundation only.

Fields:

- `workspace`
- `tenant`
- `occupancy`
- `lease` nullable
- `agreement_type`
- `reference`
- `metadata`
- `created_by`
- `created_at`

Constraints:

- all related objects must belong to the same workspace;
- if lease is supplied, lease occupancy must equal the supplied occupancy;
- linkage cannot create a second contractual truth;
- uniqueness policy must prevent accidental duplicate logical links.

## 4. Authority Boundaries

```text
Tenant          = person/entity identity
Occupancy       = space relationship
Lease           = contractual lifecycle
ContractVersion = contractual-period history
KycProfile      = current verification aggregate
KycDocument     = identity evidence
KycVerificationEvent = immutable verification history
AgreementLink   = relationship/index only
```

No P1.6 model owns rent, invoice, payment, allocation, settlement, or ledger state.

## 5. RLS Design

Every new table contains `workspace_id` and receives the same deployment pattern already used by leasing lifecycle tables:

```sql
ALTER TABLE <table> ENABLE ROW LEVEL SECURITY;
ALTER TABLE <table> FORCE ROW LEVEL SECURITY;

CREATE POLICY workspace_isolation_<table>
ON <table>
USING (workspace_id = current_setting('app.current_workspace_id', true)::bigint)
WITH CHECK (workspace_id = current_setting('app.current_workspace_id', true)::bigint);
```

The implementation must use the existing workspace context mechanism. No alternate tenant identifier or client-supplied workspace context is allowed.

RLS test matrix:

| Operation | Same workspace | Cross workspace |
|---|---|---|
| KYC profile read | allow | deny |
| KYC profile create | allow | deny |
| Document read | allow | deny |
| Document create | allow | deny |
| Verification event read | allow | deny |
| Agreement link read/create | allow | deny |

## 6. Service Transaction Boundaries

### KYC submission / verification / rejection

```text
transaction.atomic
  ↓
lock KycProfile
  ↓
validate workspace + lifecycle + documents
  ↓
mutate current state
  ↓
append one immutable event
```

A concurrent duplicate transition must result in one logical accepted transition and one history event.

### Document review

Lock the document row before validating lifecycle and changing review state. Document history/replacement must not overwrite prior evidence.

### Agreement linkage

Validate Tenant → Occupancy → Lease consistency before creation. Use transaction boundaries where duplicate/concurrent linkage is possible.

## 7. Immutability Rules

### KycProfile

Lifecycle status changes only through canonical service. Model `.save()` must reject unauthorized status changes. QuerySet `.update()` and `.bulk_update()` must not provide a lifecycle bypass.

### KycVerificationEvent

Append-only. Reject normal update, bulk update, and delete. Creation must go through canonical event helper/service.

### KycDocument

Lifecycle status changes only through canonical document service. Replacement must not mutate historical evidence in place. Bulk lifecycle mutation must be blocked.

### AgreementLink

Not inherently immutable, but business mutations must remain service-first and relationship invariants must be revalidated on every mutation.

## 8. Private Storage Design

P1.6 must not use the existing unrestricted global media semantics for sensitive KYC documents.

Preferred implementation boundary:

```text
KycDocument
   ↓
private object/storage key
   ↓
authenticated document service
   ↓
short-lived/controlled delivery
```

The exact provider adapter is implementation detail. The domain model must not expose a permanent public asset URL as its authorization mechanism.

Upload controls:

- explicit allowed MIME/type policy;
- maximum size configured;
- filename treated as untrusted input;
- no executable delivery semantics;
- sensitive values omitted from ordinary logs.

## 9. Legacy Data Strategy

Do not delete or repurpose Tenant legacy KYC fields in the first migration.

Do not fabricate verification history.

Recommended rollout:

1. create new P1.6 tables;
2. preserve legacy Tenant fields;
3. create KycProfile for existing tenants as `UNVERIFIED` only if deterministic and operationally safe;
4. do not mark legacy documents verified without historical evidence;
5. introduce new private document workflow;
6. separately plan deprecation/migration of legacy fields.

## 10. Migration Safety

Migration must be additive, RLS-enabled, and migration-check compatible.

No changes to:

- financial tables;
- Occupancy authority;
- Lease lifecycle;
- ContractVersion chain;
- existing Tenant API field meanings.

Rollback intent must not require deleting protected historical tenant/lease/financial records.

## 11. API/Data Exposure Rules

Normal Tenant serializers must not accidentally expose sensitive KYC document storage internals or unrestricted URLs.

KYC metadata and sensitive-document access are separate concerns.

Document download is an authenticated action, not a raw file field exposure.

Cross-workspace object existence must not be disclosed through error differences where avoidable.

## 12. Model-Level Acceptance Checklist

Before implementation is considered complete:

- [ ] all four models are workspace-scoped;
- [ ] all workspace relationships are validated;
- [ ] all lifecycle enums have DB-safe constraints;
- [ ] verification history is append-only;
- [ ] document replacement preserves history;
- [ ] direct and bulk lifecycle mutation bypasses are blocked;
- [ ] RLS is enabled and forced;
- [ ] same-workspace/cross-workspace tests exist;
- [ ] legacy Tenant fields remain compatible;
- [ ] no financial or Lease authority is duplicated;
- [ ] migrations pass graph/up-to-date/apply checks.
