# P0.12-D — Ledger Reconciliation

Status: **IMPLEMENTED — READ-ONLY RECONCILIATION**

## Purpose

P0.12-D compares the canonical financial source records in a workspace with the immutable financial subledger. It is a self-audit/reporting capability, not a second financial authority.

## Reconciliation findings

The reconciliation service reports deterministic findings for:

- `missing_event` — a canonical financial fact has no expected ledger event.
- `orphan_event` — a ledger event has no matching canonical source in the same workspace.
- `amount_mismatch` — the ledger amount differs from the canonical source amount.
- `relationship_mismatch` — invoice/payment/occupancy relationships differ from the canonical source.
- `unexpected_event` — the event key exists but its event type differs from the expected event type.

## Sources covered

The current reconciliation boundary covers invoice creation, recorded payments, payment allocations, advance-credit creation/application, adjustments, generated charges, late fees, final settlements, and refund lifecycle events.

Recurring invoice events retain the P0.11-D semantic rule: a recurring cycle uses the specialized `recurring_invoice_generated` event plus its underlying generated charge; it is not treated as an additional generic `invoice_created` cash/receivable event. Because the current Invoice model does not persist a direct BillingSchedule relationship, absence of a recurring event cannot be inferred solely from an invoice row; the specialized event is reconciled whenever present.

## Read-only contract

The reconciliation function only queries canonical sources and ledger rows. It does not create, update, delete, repair, reallocate, settle, refund, or otherwise mutate financial state.

No automatic repair is permitted. Findings are surfaced for an explicit future operational/accounting workflow.

## Workspace isolation

All canonical-source and ledger queries are workspace scoped. Cross-workspace records are not included in the report and cannot be treated as valid sources for another workspace.

## Determinism

Findings are returned in deterministic event-key order. Monetary comparisons use the existing Decimal financial values without float conversion.

## Protected contracts

P0.1–P0.11 financial semantics remain authoritative and unchanged. Ledger reconciliation is a projection over those contracts; it does not replace the canonical transition services or the immutable ledger.

## Deferred

- automatic repair/replay
- gateway or bank reconciliation
- accounting/GL reconciliation
- GST/tax reconciliation
- historical balance reconstruction
- bulk reconciliation UI
- external reconciliation adapters
